# 저가치 메시지 사전 필터 설계 (2026-07-08)

## 배경
- 실측(2026-07-08): 수집 메시지의 **62%가 사진(차트·캡처)**, 상당수가 잡담·짧은 반응.
- 비용 구조: `summarize`(전체 ~60%)는 클러스터 수에 비례하고, 사진은 vision 호출(~25%) + 각자 별개 클러스터가 되어 비용을 키운다.
- `dedupe_threshold` 하향은 무관한 글을 뭉치는 과병합 위험이 커서 기각(같은 날 오프라인 스윕 2회로 검증).
- 결론: 안전한 절감 레버는 **파이프라인 앞단에서 저가치 메시지를 걸러내는 것**.

## 목표
enrichment(기사수집·vision·티커 LLM 폴백)·클러스터링·요약에 태우기 **전에** 신호 없는 메시지를 제거해 vision·요약 입력 토큰을 줄인다. 신호(종목 언급·뉴스·시황 분석)는 보존한다.

## 판정 규칙 — `should_keep`
수집 직후 각 `RawMessage`에 대해 **위에서부터 순서대로** 판정(먼저 걸리는 규칙이 결과를 결정):
1. 종목/코인 검출됨(정규식 6자리 코드 · KRX 종목명 사전 · 코인 키워드 · `$US` 티커) → **유지**(`ticker`). **LLM 폴백은 쓰지 않음**(무료·결정적). 사진 캡션도 `text`에 담기므로 "캡션에 종목 있는 사진"은 여기서 유지된다.
2. 뉴스 URL 있음 → **유지**(`url`).
3. 본문(캡션 포함) 길이 ≥ `KEEP_MIN_TEXT_LEN`(=40, 모듈 상단 상수) → **유지**(`long_text`). **사진·텍스트 공통(대칭)**. 차트에 붙은 시황·수급·애널리스트 코멘트는 개별 종목코드가 없어도 신호이므로 길이로 보존.
4. 사진 있음(1~3 불충족 = 짧거나 빈 캡션) → **제거**(`photo_short`).
5. 그 외(짧은 텍스트 잡담) → **제거**(`no_signal`).

근거·검증: 초기 규칙(사진은 종목 있을 때만)은 2026-07-08 오프라인 검증에서 "#이그전 수급분석", "하나증권 코멘트", "ETF 출시 뉴스" 등 **차트형 분석 글까지 제거**함을 확인. 사용자 결정에 따라 텍스트와 동일한 길이 규칙을 사진에도 적용해 신호를 보존한다(절감폭 33%→약 23%, 신호 보존 우선).

## 구조
- 신규 파일 `src/services/message_filter.py`
  - `KEEP_MIN_TEXT_LEN: int = 40`
  - `should_keep(msg: RawMessage, ticker_dict: TickerDict) -> tuple[bool, str]` — (유지 여부, 사유). 부수효과 없는 순수 함수.
  - 종목 검출은 `TickerExtractor`의 정규식+사전 경로 재사용(LLM 폴백 미사용). 필요 시 `TickerExtractor`에 `has_ticker_no_llm(text)` 형태의 얇은 헬퍼를 추가하거나, 사전 검출 로직만 별도 함수로 노출.
- 파이프라인 삽입: `main.py::_analyze`에서 `enrich` 루프 **직전**에 필터 적용.
  - `수집 → [필터] → enrich → pre_cluster → summarize`

## 로깅(안전장치)
- 제거 건마다: `INFO  [filter] drop ({channel}) reason=no_signal | {본문 40자}`
- 요약: `INFO  filter: 총 N건 → 유지 M건(제거 K건)`
- 목적: 매 런 Actions 로그로 "무엇이 걸러졌는지" 사후 감사.

## 배포 전 오프라인 검증(핵심 게이트)
반영 전, 최근 36h 실제 수집 데이터에 필터를 적용해 **제거될 메시지 목록**을 뽑아 사용자 확인을 받는다. 과필터(신호 제거)가 없을 때만 `main.py` 배선을 반영·배포.
